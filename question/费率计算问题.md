## 费率及费用计算口径确认

我们基于现有订单数据对 WWN 与 WW 两类账户的费用计算和 OP 报文口径进行了比对，目前观察到以下差异：

- `A00071WWN`：TrnOrder `amount = 250000.00`，发送给 OP 的 `amount = 250000`，同时 OP 报文包含 `salesChargeRate = 2.00`、`salesChargeAmount = 4894.29`、`taxAmount = 391.54`。
- `S02005WW`：TrnOrder `amount = 15132.50`、`net_amount = 15000.00`、`total_charges = 132.50`，但发送给 OP 的 `amount = 15000`，且 OP 报文中的费用字段均为 0。

为确保双方系统对金额、费用、税费及 OP 报文字段的理解一致，烦请协助确认以下口径。

### 1. WWN 费用是否按“含税倒扣”方式计算

我们原先理解 WWN 的费用计算方式为：

```text
费用 = amount * 费率
```

但订单 `OD260408120654963099` 的数据与以下含 SST 的倒扣方式更为一致：

```text
total_charge = amount - (amount / (1 + r + r * 0.08))
sst_total_charge = total_charge - (r / (r + r * 0.08)) * total_charge
                 = total_charge * 0.08 / 1.08
sales_charge_amount = total_charge - sst_total_charge
```

以 `OD260408120654963099` 为例：

| 字段 | 值 |
| --- | ---: |
| accountCode | A00071WWN |
| TrnOrder.amount | 250000.00 |
| salesChargeRate | 2.00% |
| TrnOrder.total_charges | 5285.83 |
| OP.salesChargeAmount | 4894.29 |
| OP.taxAmount | 391.54 |

烦请协助确认：

1. WWN 的 `total_charges` 是否按 `amount - amount / (1 + r + r * 0.08)` 计算，而不是简单按 `amount * r` 计算？
2. SST 是否固定按 `total_charge * 0.08 / 1.08` 拆分？
3. 发送给 OP 时，`salesChargeAmount` 是否只传不含 SST 的销售费用，`taxAmount` 单独传 SST？
4. 金额四舍五入规则是每一步计算后保留 2 位，还是最终结果统一保留 2 位？

### 2. WW 场景下费用来源及 OP 报文口径

另一个场景是 WW 账号，例如订单 `OD260406102449381037`：

| 字段 | 值 |
| --- | ---: |
| accountCode | S02005WW |
| TrnOrder.amount | 15132.50 |
| TrnOrder.total_charges | 132.50 |
| TrnOrder.net_amount | 15000.00 |
| OP.amount | 15000 |
| OP.salesChargeRate | 0 |
| OP.salesChargeAmount | 0 |
| OP.taxAmount | 0 |

该场景下页面无需输入费率，但 TrnOrder 中仍存在费用：

```text
total_charges = 132.50
net_amount = 15000.00
amount = 15132.50
```

同时，目前理解是 WW 发送给 OP 时 `amount` 使用的是不含费用的金额，即 `net_amount`。烦请协助确认：

1. WW 的费用是由 UWealth 计算并扣除，还是由 OP 根据账号、基金或后台配置自动计算？
2. 如果发送给 OP 的 `amount` 不包含费用，且 `salesChargeRate`、`salesChargeAmount`、`taxAmount` 均为 0，OP 侧会通过什么规则识别该订单对应的费用？
3. WW 发送给 OP 时是否也需要传 `salesChargeRate`、`salesChargeAmount`、`taxAmount`？如果不传，费用信息通过哪个字段或哪套规则与 OP 对齐？
4. WW 的 `total_charges` 是否需要拆分 SST？如果需要，SST 的计算公式是否也与 WWN 一致？
5. 对 WW 来说，`amount`、`net_amount`、`AmountSC` 在 OP 报文中分别应该取哪个值？

### 3. 建议确认的最终口径

为便于后续开发、联调和测试，建议最终明确以下规则：

1. WWN 与 WW 的收费来源是否不同：WWN 由页面输入费率，WW 由后台配置或 OP 侧规则决定？
2. `TrnOrder.amount` 是否表示含费用总额，`TrnOrder.net_amount` 是否表示实际投资金额？
3. 发送给 OP 的 `amount` / `AmountSC` 应该传含费用金额还是实际投资金额？
4. `total_charges`、`salesChargeAmount`、`taxAmount` 三者的关系和四舍五入规则。
5. 当页面不输入费率但订单有费用时，费用信息应通过显式字段传递给 OP，还是由 OP 侧按既有规则计算或识别？
